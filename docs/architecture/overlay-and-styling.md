# The overlay and iframe styling

The overlay combines a React panel over the fullscreen player with styles applied inside YouTube's chat iframe. Both use the current `ChatProfile`. This guide explains where those parts render, how placement works, and how styling is reversed when YouTube's iframe is returned.

For chat-source selection and session cleanup, see [Content runtime](content-runtime.md). For persistence and editing history, see [Settings, state, and storage](settings-and-state.md). The [iframe stylesheet guide](../../entrypoints/content/features/YTDLiveChatIframe/styles/README.md) describes individual CSS modules and YouTube surfaces.

## Rendering and ownership

The content session has two shadow roots:

- WXT creates `wxt-react-content` on `<body>` in [`createContentSession.tsx`](../../entrypoints/content/bootstrap/createContentSession.tsx). It hosts the React tree, state, and effects.
- [`PresentationLease.ts`](../../entrypoints/content/runtime/resources/PresentationLease.ts) creates `shadow-root-live-chat` on the current player. [`Content.tsx`](../../entrypoints/content/Content.tsx) portals the overlay into this root and the on/off switch into YouTube's player controls.

Content startup requests `content-scripts/content.css` through the extension's background asset handler and supplies its text to both shadow roots. WXT uses manual CSS injection; `PresentationLease` installs a local `<style>` instead of a resource link. No CSS fetch originates in the page, so its Service Worker and Connection Allowlist cannot reject the extension stylesheet. `PresentationLease` replaces the root when YouTube replaces the player and removes it during cleanup.

The host uses `transform: translateZ(0)` outside Firefox. As a result, fixed descendants such as the settings iframe use the player as their containing block on Chrome and the viewport on Firefox. Check both engines when changing that layout.

The player-sized frame boundary uses `overflow: clip`, so focus and pointer scrolling cannot shift its coordinate origin when external resize handles extend beyond the viewport.

Within the panel, [`OverlayFrame.tsx`](../../entrypoints/content/overlay/OverlayFrame.tsx) owns the position, size, resize handles, and control rail. [`ChatSurface.tsx`](../../entrypoints/content/overlay/ChatSurface.tsx) owns clipping, hover bounds, and the shield that prevents iframe input during dragging. [`ChatViewport.tsx`](../../entrypoints/content/overlay/ChatViewport.tsx) renders the background, loading state, and iframe carrier. The runtime moves the selected chat iframe into that carrier; React does not create a replacement for a borrowed iframe.

[`useOverlayInteraction.ts`](../../entrypoints/content/overlay/useOverlayInteraction.ts) decides chat and control visibility from hover, keyboard focus, gestures, idle state, settings visibility, and document focus. The control rail fits outside the chat, preferring below, then above, then a vertical rail in a free side strip. Its measured dimensions account for changes in control size. A transparent hover bridge occupies only the outside gap, and resize hit areas also remain outside the chat so neither intercepts native controls. If no outside region fits, hovering chat does not show the rail; keyboard focus still reveals its controls, and the outer resize handles remain available to create room. Controls remain visible during dragging and resizing, and their position follows the current panel geometry, including an open placement menu. While the menu's own adjustment buttons move or resize the panel, the menu keeps its opening position and height limit so repeated clicks reach the same target. Its painted height limit is captured before the first adjustment; moving the rail does not shrink the already open menu. A direct drag/resize, viewport change, or menu reopening reanchors it. The rail continues to follow the panel without changing saved chat geometry. The rail and its placement menu stay within the player; overflowing placement actions scroll. Visible controls and menus sit above transparent resize handles for hit testing. Chat remains visible while the window is unfocused.

[`useChatInputFocus.ts`](../../entrypoints/content/overlay/useChatInputFocus.ts) observes enabled native editors in the currently attached chat iframe without reading their draft. Auto-hide keeps the chat visible while an editor is focused, even when the pointer leaves and iframe keystrokes do not reach the parent document. Leaving the editor restores ordinary idle hiding. This focus hold does not activate purchase sizing or pause movement controls. Reload, replacement, removal, and unmount release the old document's listeners and pending frame.

The placement panel arranges movement buttons as a physical directional pad around a decorative chat icon. Its grid keeps physical left/right positions in right-to-left interfaces; individual button labels retain the locale's text direction. Width and height controls form separate pairs below it, with inward/outward arrows rotated for each axis; translated labels remain visible beside the iconography. A `10 px` step indicator describes each adjustment. Its opaque surface and text follow the extension theme so custom transparent chat colors cannot make controls illegible. The panel remains bounded and scrollable in short viewports, with a footer close action returning focus to its trigger. Actions retain their original 10 px deltas and stationary click targets. Each movement/resize button repeats after a 350 ms hold, then every 80 ms; releasing a repeated pointer press does not add a final click. Space and Enter also support holding without relying on platform key-repeat speed. Leaving the button, cancelling the pointer, losing focus/visibility, closing the panel or unmounting ends the repeat session. The close action does not repeat. Adjustment availability uses the same fitted candidate as committing geometry; directions that cannot change position or size are disabled and dimmed, and reaching a disabled limit stops held input. The panel can restore the geometry and pinned intent captured when it opened, writing only the geometry domain. Reopening starts a fresh restore point; viewport fitting still applies to restored settings.

The placement menu closes on an outside pointer press or before settings opens. [`useOverlayMenuDismiss.ts`](../../entrypoints/content/overlay/useOverlayMenuDismiss.ts) observes the parent document and the current borrowed chat document only while the menu is open; it never prevents or replays the outside action. Iframe reload/replacement and unmount release its old listeners. Direct drag/resize controls are part of the same placement flow and retain the existing menu-follow behavior. Settings readiness changes clear the menu so closing settings cannot resurrect it. Keyboard focus leaving the rail also closes placement while preserving the new focus target. Reaching an adjustment limit can disable its focused button; that native focus loss keeps the current adjustment panel open.

Control icons show localized visual help after a continuous 200 ms hover or immediately on browser `:focus-visible` keyboard focus, using their existing translated accessible labels and movement description. Tooltip text and its opaque background use the extension theme’s dedicated tooltip colors, independent of custom chat foreground, background and alpha. This keeps help readable even for transparent or same-color chat settings. Leaving a hovered icon and its help, switching icons, opening placement, starting gestures and unmounting cancel pending hover help. Keyboard focus replaces stale hover help. Pointer presses clear keyboard help even on an already focused button; click focus and focus returned after a pointer closes the placement panel do not retain tooltips after the pointer leaves. Keyboard input on a pointer-focused control can enable keyboard help without requiring another focus event. Help is centered on the active button, placed 6 px below the rail when space permits, and moved above it at the player's bottom edge. Horizontal placement retains an 8 px player inset. Its measured position follows geometry, viewport, translation and font-size changes; help ignores pointer events and is hidden during an open placement menu or active drag/resize. The visual copy is hidden from assistive technology because the controls already expose the same accessible name and description.

Escape dismisses visible pointer help until its hover trigger changes, and focused help until focus changes. Pointer departure does not restore help that was dismissed while its button still has keyboard focus. [`useOverlayTooltipDismiss.ts`](../../entrypoints/content/overlay/useOverlayTooltipDismiss.ts) listens only while that help is displayed, in its owner document and the currently attached accessible chat document. Native controls can consume Escape first, and IME composition keeps the key. Iframe replacement, hiding help and unmount remove the previous listeners. Dismissal preserves the native editor's focus and draft.

[`useOverlayTooltipHover.ts`](../../entrypoints/content/overlay/useOverlayTooltipHover.ts) keeps displayed hover help readable as the pointer crosses the short gap or moves over the help. Passive pointer tracking covers the owner document and currently attached chat document; chat viewport coordinates are converted to the owner's painted space. The help retains `pointer-events: none`, so clicks still reach native video or chat controls beneath it. Leaving the combined trigger/help region releases that hold. Hidden help, iframe replacement and unmount release its listeners and observers.

[`useDocumentFocus.ts`](../../entrypoints/content/hooks/watchYouTubeUI/useDocumentFocus.ts) reads `document.hasFocus()` immediately on window focus/blur and document visibility changes, then samples it once on the next animation frame. Firefox can report a transient unfocused state inside the parent window's blur event while transferring focus into the chat iframe, followed by a focused document without another parent focus event. The deferred sample clears that stale state so normal idle hiding resumes; a genuinely unfocused window continues to keep chat visible. Event bursts share one pending frame, and unmount cancels it and removes the listeners.

Use the layer constants in [`zIndex.ts`](../../shared/constants/zIndex.ts) for stacking. Keep `data-ylc-*` hooks synchronized with the [E2E page object](../../e2e/pages/ExtensionOverlay.ts) and browser inspection/capture scripts when changing the DOM.

Screen-reader descriptions and live announcements use the shared `.ylc-visually-hidden` utility in [`controls.css`](../../shared/styles/controls.css), loaded by both content and settings roots. Keep their accessible relationships and live-region attributes on the owning controls.

The control rail's surface and icons use the extension theme independently of the chat's custom foreground, background and alpha. Settings, dragging and placement remain discoverable even when a custom chat palette is transparent or uses identical text and background colors. Each rail button, including the drag handle, owns its visible keyboard focus indicator. The rail declares its selected interface language and direction locally, including its placement controls and help, while YouTube's page and chat documents retain their own attributes.

## Geometry and input

[`useOverlayGeometry.ts`](../../entrypoints/content/overlay/useOverlayGeometry.ts) renders stored geometry against the current player size. Current settings store player-relative ratios and a `pinned` flag; legacy pixel settings are converted after a usable player rectangle is available. Size limits and conversion functions live in [`chatGeometry.ts`](../../shared/settings/chatGeometry.ts). Rendering and commits also pass through [`fitGeometryToViewport.ts`](../../shared/settings/fitGeometryToViewport.ts), which clamps position and size while preserving the 240 × 180 px minimum. Players smaller than that minimum can still overflow.

Drag and resize share [`usePointerSession.ts`](../../entrypoints/content/overlay/usePointerSession.ts):

1. A primary-button pointerdown starts one session. `data-ylc-resize-direction` on the handle selects resizing; the drag button starts movement.
2. Pointer movement updates an in-memory pixel draft, coalesced to animation frames. Resize calculations preserve the opposite edge before fitting the result to the available space.
3. Pointerup derives the final layout from the release coordinates and commits once as pinned geometry.
4. Escape, pointer cancellation, lost capture, window blur, or unmount cancels the draft without saving it.

Pointer move, release, and cancellation listeners run on the window in the capture phase. A host-page handler that stops propagation below the window must not suppress the final position commit and turn the browser's subsequent capture release into an unintended rollback. A completed release commits once, and relinquishing capture cannot cancel that completed session. Explicit cancellation and genuine lost capture retain their rollback behavior.

Resize previews honor the same player-relative maximum dimensions as persisted geometry, as well as the space between the fixed opposite edge and the padded viewport boundary. Clamp the requested size before deriving left/top coordinates so reaching a limit does not shift the opposite edge or shrink the panel on pointerup. Single-edge handles ignore movement along the perpendicular axis; corner handles resize both dimensions.

The drag button's arrow-key controls and the placement menu move the panel in 10 px steps. The menu also resizes in 10 px steps. These actions commit pinned geometry and do not run during a pointer gesture or while settings are open.

Automatic placement applies only to unpinned geometry while no gesture or draft is active. [`collectPlayerObstacles.ts`](../../entrypoints/content/platform/youtube/collectPlayerObstacles.ts) measures captions, controls, menus, the end screen, and the settings area. [`autoSafeArea.ts`](../../entrypoints/content/overlay/autoSafeArea.ts) compares the current placement with corner candidates and moves only when its overlap and improvement thresholds are met.

[`useAutomaticOverlayPlacement.ts`](../../entrypoints/content/overlay/useAutomaticOverlayPlacement.ts) owns obstacle snapshots, observation, and automatic-placement decisions. Obstacle mutations are measured once per animation frame, and unchanged rectangles do not trigger a React update. Obstacle observation stops after a successful automatic move or when geometry becomes pinned; player-size observation continues. `useOverlayGeometry` schedules the reset, observation, and placement effects around player measurement and legacy migration in their original order. Auto-placement is separate from chat-runtime reconciliation.

Preset pointer reordering starts after 6px of vertical movement. A themed, noninteractive floating preview follows the pointer while a dashed placeholder identifies the proposed insertion slot; storage changes only on drop. The handle remains focused after drop. Escape, pointer cancellation, lost capture, blur, unmount, or an external list update cancel the gesture and release its resources. A press without movement does not reorder or start edge scrolling. Built-in presets use the same named deletion confirmation as custom entries.

Preset creation focuses and selects the new custom name only after a successful local add. External additions never request focus. Deletion dialogs show the literal preset name (or the localized untitled fallback) and include it in their accessible description. Preset rows compare the entire effective appearance/display profile to their stored or built-in profile: matching rows alone show a check and localized current-state text, with `aria-pressed` on the apply button. Identical profiles may match more than one row. Live edits, Undo and external appearance changes update the indicator; geometry and names do not affect a match. Applying an already matching profile is a no-op and preserves keyboard focus.

Preset deletion confirmations stay within the viewport with a 12 px vertical inset. Their heading and actions remain visible while the named description region scrolls for long names or short viewports. The region is in the keyboard focus order so native scrolling keys can reveal the full target name and confirmation question before Cancel or Delete; cancellation and Escape preserve the stored presets and return focus to the deletion trigger.

Preset reordering has a separate [`usePresetReorder.ts`](../../entrypoints/content/features/YTDLiveChatSetting/components/PresetContent/usePresetReorder.ts) session. Pointer and keyboard moves share the order, preview, and announcement update. Each lifted gesture owns its listeners, pointer capture, and auto-scroll frame through one disposable resource owner; a callback from a finished gesture cannot affect the next one. The stationary scroll container or list captures the pointer so moving a row does not cancel the gesture. Preview changes stay in memory until confirmation. Escape, blur, lost capture, or an external list change cancels them.

## Settings previews and committed styles

The settings UI runs in its own extension-origin `settings.html` iframe and Jotai store. Continuous controls edit a draft; completing a gesture saves the appearance once. [`useSettingsStylePreview.ts`](../../entrypoints/settings/useSettingsStylePreview.ts) sends the draft profile to [`SettingsFrame.tsx`](../../entrypoints/content/settings/SettingsFrame.tsx) once per animation frame so the content overlay updates during editing.

Modal backdrop dismissal requires the same primary pointer to start and end on the backdrop. A text-selection or other drag that starts inside the content cannot close the modal when released outside. Cancelled or mismatched pointers do not arm dismissal; genuine backdrop clicks and Escape retain their ordinary behavior, including nested modal ownership.

The settings panel fits the viewport with 12 px margins. Its header and footer remain visible while the body scrolls vertically, without horizontal overflow in either left-to-right or right-to-left locales. At panel widths up to 400 px, history/close actions occupy a separate row above equal-width tabs. Long translated tab labels can wrap without displacing those actions. Settings and Presets retain independent scroll positions for the mounted settings session; a tab's first visit starts at the top, and returning restores that tab's position within its current native scroll bounds.

Font search keeps focus in its combobox input and identifies the active option with stable listbox/option IDs. Arrow navigation scrolls only the local options list to reveal the active option; the popup height is bounded by the settings body. When a trigger and usable popup fit only without the preferred scroll margins, visibility scrolling reduces those margins to keep both controls inside the body. Scrolling a candidate under a stationary pointer does not replace the keyboard-active option; actual mouse movement can select it. Selection and Escape return focus to the trigger, while Tab closes the popup and continues to Text Size without stopping on the scrollable list itself. IME composition keys remain with the input method. Enter chooses a font only after composition has finished, so confirming search text does not also change the saved appearance or undo history. With no matching candidates, Enter leaves the popup, search, current font, storage and undo history unchanged. Selecting the explicit Default option still restores the default font.

Text size, blur and message spacing keep their range sliders and also accept direct integer input. Typing stays local; Enter or blur clamps a valid integer to the field limits and commits once through the existing appearance history. Empty, fractional or invalid input restores the current value without saving. Escape restores the current value while retaining input focus; composition keys remain with the input method. An external update to the same setting invalidates the unfinished edit, while updates to unrelated settings remain intact. Removing the settings UI does not save unfinished typing.

Each color picker treats its trigger and internal sliders as one focus region. Moving between those controls leaves the picker open; moving focus to another color, Font or any outside control closes it without taking focus back. This prevents keyboard activation from leaving overlapping pickers behind. When Escape reaches a color-picker control or its trigger, it closes that picker and returns focus to the trigger before the settings modal can handle the key. Closing the picker finishes its active appearance gesture through the same cleanup used for removal. A browser-owned Escape can exit native fullscreen before content receives a key event; fullscreen teardown then closes settings and releases chat resources.

Settings tabs support arrow navigation in the displayed direction and Home/End for the first/last tab, with focus and selection moving together. Modified keys and IME composition remain with the browser or input method. The font trigger retains its setting label and describes the currently selected font; its named listbox reports search-result counts through one live region rather than announcing the whole option list. Color triggers identify their open dialog with `aria-controls`, and each dialog describes its target color field. Direct numeric inputs associate the visible pixel unit with their accessible description. Technical color values and numeric value/unit pairs retain left-to-right ordering inside right-to-left settings. Color popups align to the inline end of their trigger so right-to-left layouts expand into the available panel space. Popup visibility scrolling is instant when the user prefers reduced motion; ordinary scrolling retains its smooth behavior.

The receiver checks the message source, allowed origin, and profile schema. The preview is transient and remains visible until the matching Storage commit arrives, so an earlier save cannot overwrite a later gesture. Closing or reloading the settings frame clears it. Committed settings converge through Storage; see [Settings, state, and storage](settings-and-state.md) for ordering and failure behavior.

The effective profile reaches [`ResourceReconciler.ts`](../../entrypoints/content/runtime/ResourceReconciler.ts), which applies it to a usable chat document:

1. [`compileStylePatch.ts`](../../entrypoints/content/style/compileStylePatch.ts) converts appearance settings into document/body properties and a font selection.
2. [`applyStylePatch.ts`](../../entrypoints/content/style/applyStylePatch.ts) writes those properties and delegates font loading to [`fontLoader.ts`](../../entrypoints/content/style/fontLoader.ts).
3. The ordered modules in [`styles/index.ts`](../../entrypoints/content/features/YTDLiveChatIframe/styles/index.ts) consume the properties. [`iframeInitializer.ts`](../../entrypoints/content/features/YTDLiveChatIframe/utils/iframeInitializer.ts) injects their combined stylesheet once per document using a marker attribute.

The compiler owns color, spacing, font size, display flags, and blur values. YouTube's default membership color is read only when that mode is selected; custom colors compile directly from the profile. Font requests accept only names allowed by [`fontFamilyPolicy.ts`](../../shared/utils/fontFamilyPolicy.ts).

The React background and iframe document use `backdrop-filter`. Never apply `filter: blur(...)` to the iframe host, which would blur the chat text. The iframe body and inner surfaces use the configured backdrop value; the stylesheet guide explains surface tinting and cascade order.

The attached iframe owns the chat viewport even before a purchase begins. Under the extension body class, `frame.css` clears `yt-live-chat-app`'s native minimum width and height so a small overlay can reach the native composer and purchase entry. Removing the class restores YouTube's minimums. The message scroller uses a thin, secondary-color scrollbar and contains vertical overscroll; reaching either end must not scroll the outer YouTube page.

Text links in ordinary chat messages and viewer-engagement message copy use an opaque blue calculated by [`linkColor.ts`](../../entrypoints/content/style/linkColor.ts), plus an underline and wrapping for long URLs. The calculation compares contrast over the configured background composited against black and white video extremes, choosing the blue with the better worst-case result. Fully transparent backgrounds use the configured text's light/dark direction. Neither arbitrary partial opacity nor full transparency guarantees a minimum contrast over every moving video frame. Button-shaped anchors, native paid-card color pairs, and outer purchase pages retain their own colors.

Collapsed pinned comments draw their overflow ellipsis on the text renderer's `#content` block. Theme that block with the configured primary text color as well as its message children; otherwise YouTube's native block color remains visible in the ellipsis. Keep this rule inside the pinned banner and collapsed-renderer boundary so normal messages and author badge color pairs retain their own styles. Chromium can retain the old marker pixels after a color update. On the first styled profile application and primary text color changes, `applyStylePatch` calls [`refreshPinnedMessageEllipsis.ts`](../../entrypoints/content/style/refreshPinnedMessageEllipsis.ts) to temporarily switch only those blocks to clipping, flush layout, and restore their inline value and priority synchronously. Repeated unchanged profiles and background-only changes do not run this refresh; there is no message observer, timer, panel resize, or text replacement.

Inline monetization offers use the profile's neutral surface and text colors, including the Super Sticker preview's close/return controls and the membership gift quantity selector. Enabled Text quantity actions use a transparent resting fill and the configured interaction tint on hover or visible keyboard focus, so YouTube's opposite light/dark hover fill cannot conflict with the custom text. Preserve Filled, Tonal and disabled button pairs, colored purchase cards, artwork, and paired sticker-backstory colors. Scope these rules to the borrowed chat document; outer membership and payment dialogs keep YouTube's native palette.

The legacy and revamped Super Chat amount inputs, heading, metadata and purchase disclaimers follow the profile at their explicit native boundaries. Validation errors, over-limit counters and disabled purchase actions retain native semantics. Neutral purchase links use the readable link color and an underline. Super Sticker preview headers and enabled pack-navigation icons follow the profile; never recolor arbitrary pack SVGs, price chips or paid artwork. Gift offers release desktop negative section margins and include header padding in their width so quantity actions remain inside narrow frames.

Native purchase menus and offers remain in fullscreen. The iframe purchase observer keeps chat visible and prevents chat-only chrome from collapsing or blurring a purchase input while the native picker, offer, or an in-progress offer spinner is visible. Retained hidden panels and initial chat loading do not count as a purchase. A temporary minimum panel size of 360 × 480 CSS pixels is bounded by the player viewport; closing the native UI restores the saved geometry without writing settings. Extension move and resize controls pause until the native UI closes so the transient layout cannot accidentally become the saved layout. Purchase surfaces scroll within smaller viewports. The observer releases with its document, including reload/replacement and borrowed-iframe restoration. Both the overlay activity observer and chrome lease rebind when the same document gains or replaces its body without an iframe load event, releasing the previous body's observers and presentation state. Only an already-open flow in the same iframe and document can continue through a replacement body's native loading spinner; initial loading and loading in another document or iframe remain inactive.

Buy Jewels is also an active purchase surface, identified by its visible `pdp-view-model` rather than the gift catalog. Its engagement-panel header uses the configured neutral foreground. The options, terms and checkout footer share a viewport-bounded scroll area; native minimum column widths and nested height caps are released only inside that panel. An 8px scrollport inset and native focus-target margins keep keyboard-focused checkout controls fully visible, including Firefox's partially visible focus boundary. Native price-card and checkout-button color pairs remain unchanged. Gift announcement author and message wrappers use the configured foreground while explicit semantic runs and gift artwork retain their native colors.

The selected native purchase page, including live-chat donation amount selection, scrolls within `#panel-pages`; the floating product picker instead has its own viewport cap and scroll area. Both use thin, secondary-color scrollbars with transparent tracks and contain overscroll. Keep overflow visible on ordinary and restricted-participation input boundaries while the picker is open, since clipping their short input page would hide the menu. During that state only, place the input boundary above the native chat header so a picker overlapping the header remains clickable in a very short viewport. Retained hidden purchase pages must not change the resting input page's overflow. The native input page is a sibling of the selected offer inside these pages, rather than an extra footer reserved below it. Release fixed sticker-pack heights and gift-offer inner scroll caps only while their purchase page is selected, leaving one outer vertical scroller. Native focus targets have an 8px reveal margin. Only `[live-chat]` donation pickers activate the inline purchase hold; non-chat donation dialogs are excluded, and donation card/action color pairs remain native. Restore the donation container's base-background/primary-text pair explicitly because shared transparent chat tokens otherwise clear its action-panel fill; wrap suggested amounts within narrow live-chat cards. Attribute-qualified purchase probes observe their tag and marker changes so hiding the root or removing `[live-chat]` releases the hold.

YouTube owns all purchase, join, send, price-selection and confirmation actions. The extension does not cancel or replay these clicks, replace the Membership entry with a new-tab redirect, or automatically leave fullscreen. The native fullscreen control remains available to the user. Firefox can give Escape to the browser's fullscreen controller even while an extension menu is focused; the regular borrowed-iframe restoration runs on that exit. Closing the placement menu with its toggle or close button keeps fullscreen. Pre-confirmation verification does not establish payment completion or server-side billing outcomes.

Viewer poll cards float over messages and share the support picker's minimum-opacity surface. Theme question/choice labels, neutral controls and result-bar fills within the poll boundary. After answering or closing a poll, YouTube uses a separate `yt-live-chat-banner-poll-renderer` with `yt-live-chat-banner-poll-choice` results. Its collapsed summary, expanded question/results and overflow-menu SVGs follow the configured primary text color; expanded metadata follows the secondary color. The banner retains its existing surface. YouTube continues to own percentage widths, selected/disabled state and voting; styling must not alter those values or submit an action.

## Restoring a borrowed iframe

Before styling a borrowed document, [`iframeAttachment.ts`](../../entrypoints/content/features/YTDLiveChatIframe/utils/iframeAttachment.ts) captures its original presentation through [`borrowedIframeStyleSnapshot.ts`](../../entrypoints/content/features/YTDLiveChatIframe/utils/borrowedIframeStyleSnapshot.ts). That module owns the inline properties, their priorities, the body's backdrop filters, and any existing custom-font style. Attachment still owns when each document is captured and restored. Release restores those values and removes extension classes, measurement variables, injected styles, and event fallbacks. Unrelated YouTube styles remain untouched. Managed iframes are removed on release.

When adding a property, update [`YLC_DOCUMENT_STYLE_PROPERTIES`](../../entrypoints/content/hooks/ylcStyleChange/ylcStyleConstants.ts) and the snapshot/restore code as needed. A property absent from the snapshot can remain in YouTube's native chat after release. Keep shared body classes and marker names in [`styleContract.ts`](../../entrypoints/content/features/YTDLiveChatIframe/constants/styleContract.ts).

Chat-only mode collapses the header and input through [`ChatChromeLease.ts`](../../entrypoints/content/runtime/resources/ChatChromeLease.ts). Its measurement reads and transition classes establish the animation's start height; removing them can turn the transition into a jump. Preserve header overflow outside chat-only mode so YouTube's chat-mode menu remains visible.

When chat-only chrome is collapsed, the renderer leaves 12 px at both vertical edges, outside its native content pages and message scroller. On hover, each edge with a rendered header or input animates to zero padding over the same 260 ms as that native chrome; a replay without an input keeps its bottom inset, and a headerless replay keeps both. `ChatChromeLease` measures which edges have chrome and owns their padding targets separately from temporary measurement classes, so measurement does not switch padding or box sizing. The `chat-only-mode` class keeps border-box sizing throughout hover. Purchase UI uses the full viewport, and exiting chat-only mode or releasing the document removes the padding targets and mode class.

Padding belongs to the renderer itself: current YouTube nests the outer `#contents` below `#content-pages` and `#chat-messages`, while another `#contents` absolutely positions the message scroller. Message spacing and the outer iframe size stay unchanged. The ticker has no additional top margin.

During chrome transitions, `ChatScrollAnchor` keeps bottom followers at the latest message and preserves a history reader's visible row at the same iframe coordinate, within the native scroll bounds. It captures only a DOM reference and geometry, never message text. Compensation lasts only for the transition and yields immediately to wheel, touch, pointer or scroll-navigation keys, including the native jump-to-latest button. Native purchase UI, gestures, document replacement and release stop it. Temporary `overflow-anchor` and `scroll-behavior` overrides are restored with their original inline priorities; newer native writes are preserved. While a transition keeps a bottom follower at the latest message, a temporary body class hides the native `#show-more` control to prevent native resize detection from flashing it. History readers retain the control; cancellation, manual input and release remove the class, and synchronous measurement does not own it. Ordinary message arrival remains owned by YouTube.

## Accessible extension controls

Popup and settings controls follow the [Digital Agency accessibility guidance](https://design.digital.go.jp/dads/guidance/accessibility/) and [Apple Human Interface Guidelines](https://developer.apple.com/design/human-interface-guidelines/accessibility) for legibility, recognizable actions, keyboard operation, and adapting to the available space. Apply their principles to this browser extension rather than copying a native platform's visual style.

Theme text must retain at least 4.5:1 contrast on the surfaces where it appears. Editable control boundaries and keyboard focus indicators target 3:1 against their surrounding surfaces. `--ylc-control-border` identifies inputs without darkening decorative separators, `--ylc-accent-text` provides readable text on soft accent fills, and `--ylc-focus-ring` is opaque in both themes. Color-picker focus uses a visible outline and a black/white pointer boundary; it does not rely on scaling the pointer. Forced-color rendering keeps switch states, range tracks, and selected versus keyboard-focused theme options distinguishable.

Popup theme choices, backup actions, and destination links retain visible labels. At narrow widths labels and editors stack while toggle rows remain one large label target. Settings editors also stack below 360px panel width, and translated labels wrap without overlapping their controls. Color codes and numeric values with pixel units retain left-to-right ordering inside right-to-left interfaces. Touch-oriented controls grow to at least 44 CSS pixels when the primary pointer is coarse; desktop settings keep their compact layout. Narrow touch preset cards place their actions below the name and let translated labels wrap, keeping every target inside the card. Destructive confirmation uses a solid red/white pair with sufficient text contrast in both themes. In forced-color mode, color swatches and the color picker preserve their actual colors and transparency grid because they represent the value being edited. The surrounding interface and keyboard outline continue to use system colors.

[`mountExtensionPage.tsx`](../../shared/runtime/mountExtensionPage.tsx) keeps each extension document's `lang` and `dir` synchronized with its selected locale, including body portals. It does not change the host YouTube document. Native language names in the language selector identify their own language. The save-failure notice has its own theme and locale direction in both popup/settings and the standalone compact content surface. It uses opaque error colors and a keyboard-visible Retry action independent of custom chat colors or OS appearance. Retry remains visible and busy while persistence is pending, then clears only after success; a failed retry leaves the error available. The backup confirmation gives its apply action a filled primary treatment while retaining Export and Cancel.

A font search with no matching candidates retains the visible empty message and live result count, while exposing no empty listbox or expanded suggestions. Correcting the query restores the named listbox and its `aria-controls` relationship. Enter with no candidate preserves the selected font and Undo history.

The settings tabpanel explicitly uses `tabIndex={-1}`. Firefox otherwise makes the overflow scroll container an implicit Tab stop; excluding that intermediate stop lets the modal's keyboard order continue from the header to the switches and field controls. Firefox can reserve Escape for leaving fullscreen before an extension document receives `keydown`; keep visible close actions available for local dismissal. Fullscreen exit remains a browser action, as described in the [Fullscreen API guide](https://developer.mozilla.org/en-US/docs/Web/API/Fullscreen_API/Guide#getting_out_of_full_screen_mode).
