## Generated output

The generator owns `public/locales/`, `public/_locales/`, and `shared/i18n/generated/`. Do not edit these trees by hand or use them to store unrelated files. Write mode rebuilds the generated directories.

Runtime bundles are positional arrays. `_keys.json` supplies their order, so a key change requires regenerating every affected bundle, not just the edited language. The loader validates the bundle before exposing it as `LocaleMessages`. Manifest messages and runtime messages have different consumers; their mapping belongs to the compiler.

`LocaleCode`, `TranslationKey`, and `LocaleMessages` are generated from the authored inputs. `useT()` returns a translator accepting `TranslationKey`, not arbitrary strings. Components that receive translation keys must preserve this type in their props and callbacks. Use a typed mapping for dynamically selected keys rather than casting a general string.

Before hydration the translator can return a recognized key as a fallback. Normal entrypoints await application runtime initialization before rendering, so incomplete locale state is not the normal UI startup path.

## Locale selection and persistence

Locale is one of the five independently owned settings domains. The complete storage, compatibility and retry contracts are documented in [settings and state](./settings-and-state.md), not repeated here.

A stored selection takes precedence over compatibility data and the browser UI language. Language resolution is centralized in `language.ts`; consumers should not invent their own alias or region rules.

A local `setLocale` request loads messages before updating the rendered locale and saving the selection. A request identifier prevents an older asynchronous load from replacing a later selection. Storage failures keep the selected language visible locally and are reported through the shared persistence notice. External committed selections also load their messages before being applied without a write echo.

Returning to the already-rendered language invalidates an older external load even though the rendered code needs no update. Conversely, an unchanged save acknowledgement does not cancel a newer local language request. The runtime tracks which pending request came from a watched commit rather than treating every equal value as either an unconditional no-op or a cancellation.

When a selected bundle cannot be loaded, initialization and switching can use the English base messages. The selected locale code remains the user's preference. If even the base messages are unavailable, initialization fails or an already-running context retains its rendered messages. The loader owns cache behavior; do not add a second cache in UI components.

Direction is derived from generated RTL metadata through `rtl.ts` and `localeStateFromMessages`. Updating a direction rule requires changing its authored compiler input and regenerating metadata, not hand-editing the output.

## Maintaining translations

For text changes, edit `shared/i18n/assets/<code>.json` and regenerate. For a key addition or rename, update all authored locales to match the English shape, regenerate the bundles and types, and update typed call sites. For a new language, also update its display name and applicable store-listing inputs.

The local verification entrypoint is `yarn verify`; it includes locale and store checks as well as source checks and tests. Targeted generation and inspection commands are:

```bash
node scripts/generate-locales.mjs
yarn locales:check
yarn store:check
```

These are maintainer instructions, not evidence that a particular change has been verified. Store copy has its own validation in [`check-store-listing.mjs`](../../scripts/verify/check-store-listing.mjs); a locale compiler success does not establish store compliance or translation quality.

## Boundaries to preserve

Every authored locale must have the required key shape, and generated output must agree with the compiler. Untrusted stored locale values are resolved at the settings boundary. Normal UI calls use generated translation keys. Message loading never silently overwrites a newer selection, and applying a committed locale never echoes it back to Storage.

Locale delivery does not establish the linguistic quality of translations or complete accessibility of every RTL layout. Review the affected interface in a browser when changing those behaviors.
