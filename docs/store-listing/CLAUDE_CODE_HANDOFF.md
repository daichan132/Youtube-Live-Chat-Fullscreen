# Chrome Web Store 掲載情報改善の引き継ぎ

## 依頼

Chrome Web Store の掲載情報を、機能の正確さを保ちながら、初見の利用者が用途と利点を短時間で理解できる内容へ改善してください。調査や提案だけで終わらせず、対象ファイルを更新し、生成物と検証結果まで揃えてください。

この作業ではローカルファイルだけを変更します。Chrome Web Store デベロッパーダッシュボードの「下書きとして保存する」と「審査のため送信」は操作しないでください。公開、リリース、コミット、プッシュも、この依頼には含みません。

## 最初に確認するファイル

- `docs/store-listing/chrome-dashboard-snapshot-2026-08-19.json`
- `docs/store-listing/*.md`
- `shared/i18n/assets/*.json`
- `scripts/generate-locales.mjs`
- `scripts/verify/check-locales.mjs`
- `CONTRIBUTING.md` の Translations と Screenshots

スナップショットは、2026年8月19日に `daichan` Chromeプロファイルの Chrome Web Store デベロッパーダッシュボードから読み取った55言語分の掲載情報です。作業開始時点の比較基準として扱い、上書きしないでください。

## 現在の状態

管理画面には55言語が登録されています。スナップショットには、各言語のタイトル、概要、説明、管理画面の文字数、ローカライズ版動画、ローカライズ版スクリーンショット数を収録しています。

管理画面とリポジトリを照合した結果は次のとおりです。

- 55言語すべてで、タイトルと概要が `public/_locales/*/messages.json` の内容と一致しています。
- 54言語の説明が `docs/store-listing/*.md` と一致しています。
- `pt-BR` だけは一致しません。ローカルの `docs/store-listing/pt_BR.md` にある Opera 向けトラブルシューティング段落が、管理画面にはありません。
- ローカライズ版プロモーション動画とローカライズ版スクリーンショットは、全55言語で未設定です。
- 全言語向けスクリーンショットは3枚です。
- 全言語向けプロモーション動画、小プロモーションタイル、マーキープロモーションタイル、サポートURLは未設定です。
- ストアアイコン、公式URL、ホームページURLは設定済みです。

## 改善の目的

掲載情報は、次の問いに上から順に答える構成にしてください。

1. 何ができる拡張機能か。
2. YouTubeの通常のフルスクリーン表示と何が違うか。
3. チャット投稿、Super Chat、配置変更、見た目の調整、プリセット、アーカイブ再生のうち、利用者にとって主要な利点は何か。
4. アカウント、データ収集、オープンソースについて、どのような安心材料があるか。
5. インストール後に何をすれば使えるか。
6. 問題が起きた場合に、どこで解決方法を確認できるか。

タイトルと概要は検索結果で単独表示されても用途が伝わるようにしてください。説明は機能一覧を並べるだけでなく、利用場面と利点を対応づけてください。確認できない機能、対応ブラウザ、プライバシー上の保証は追加しないでください。

## 作業内容

### 1. 英語と日本語の基準原稿

英語と日本語を意味上の基準原稿として先に改善してください。両言語で、機能の優先順位、段落構成、手順、サポート導線を揃えます。単語を逐語的に対応させる必要はありません。

次の点を検討してください。

- 「50以上の言語」を、現在の実数である55言語と表現するか。
- 冒頭で「フルスクリーンでもチャットを表示できる」ことを、より短く明示できるか。
- 機能名ではなく利用者の利点から説明できるか。
- GitHubだけでなく、設定予定のサポートURLへ誘導するほうが分かりやすいか。
- 長い機能一覧と利用手順に重複がないか。

### 2. 残り53言語

英語と日本語の基準原稿が固まった後、残り53言語を更新してください。各言語では、情報の欠落を防ぎながら、英語の語順をそのまま移した不自然な文を避けます。

タイトル、概要、説明の役割を混同しないでください。概要には主要な用途と差別化だけを置き、細かな設定項目や利用手順は説明へ移します。右から左へ書く言語では、既存のRTL対応を壊さないことも確認してください。

### 3. `pt-BR` のずれ

`pt-BR` だけに Opera 向けトラブルシューティング段落がある状態を解消してください。長いトラブルシューティングを一言語のストア説明へ置く方針は採用しません。

次のいずれかを、リポジトリ内のサポート導線と実装上の根拠を確認して選んでください。

- Operaを掲載情報で扱わず、`pt_BR.md` から当該段落を削除する。
- Opera対応を短い互換性情報として全言語で統一し、詳しい手順はサポートページへ移す。

ユーザーはOpera対応を重視しています。ただし、掲載文に対応を明記する場合は、現行実装と検証記録で裏付けられる範囲に限定してください。

### 4. サポート導線

管理画面のサポートURLが未設定です。既存のドキュメントサイトまたはGitHubの適切なページから、ストア利用者向けの入口を一つ選び、設定候補と理由を成果報告に記載してください。

この作業では管理画面へ入力しません。リポジトリ内にサポートページやリンクの修正が必要であれば実装してください。外部サービスへの送信は、別途ユーザーが明示的に依頼したときだけ行います。

### 5. 画像とプロモーション素材

現在は全言語向けスクリーンショット3枚だけが設定されています。既存の `yarn capture:store-assets` で再現可能な範囲を確認し、次の不足を評価してください。

- スクリーンショットだけで、フルスクリーン表示、投稿、配置変更、スタイル調整が伝わるか。
- ローカライズ版スクリーンショットを用意する価値が高い言語はどれか。
- 小プロモーションタイル、マーキープロモーションタイル、プロモーション動画を追加すべきか。

既存の自動生成フローで安全に作れる素材は実装して構いません。デザイン判断や手作業が必要な素材は、必要サイズ、コピー、構図、対象言語を具体化した作業リストを作成してください。説明のない画像差し替えや、未確認のベースライン更新は行わないでください。

## ファイルの扱い

拡張機能名と概要のソースは `shared/i18n/assets/*.json` です。`public/locales`、`public/_locales`、`shared/i18n/generated` は生成物なので、直接編集しないでください。

説明文は `docs/store-listing/*.md` を更新します。言語コードは、管理画面の `iw` がリポジトリでは `he`、ハイフンを含むコードがリポジトリではアンダースコアになる点に注意してください。

作業開始時に `git status --short` を確認し、既存の未追跡スナップショットを保持してください。リセット、スタッシュ、チェックアウトによる破棄は行わないでください。

## 検証

少なくとも次を実行してください。

```bash
node scripts/generate-locales.mjs
yarn locales:check
yarn check
```

ストア画像を変更した場合は、次も実行し、変更画像を原寸で確認してください。

```bash
yarn capture:store-assets
```

掲載情報向けの文字数制限、55言語の欠落、生成物のずれ、管理画面スナップショットとの差分を自動検出できる検証が不足している場合は、検証スクリプトとテストを追加してください。制限値は推測で固定せず、現在の Chrome Web Store の仕様または管理画面表示で確認してください。

## 完了条件

- 55言語すべてに、空でないタイトル、概要、説明がある。
- 英語と日本語で、用途、主要機能、利用手順、プライバシー説明、サポート導線が矛盾していない。
- 残り53言語に、基準原稿の情報が欠落なく反映されている。
- `pt-BR` だけにOperaの長い説明が残る不整合が解消されている。
- 生成対象のファイルを直接編集していない。
- 必須の検証コマンドが終了コード0で完了している。
- 変更した掲載文がストアの文字数制限内に収まっている。
- 管理画面への保存、審査送信、公開を行っていない。
